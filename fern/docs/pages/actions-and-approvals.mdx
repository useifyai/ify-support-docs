ify can take action on a ticket, not just reply to it. Actions run through the appropriate connected apps — ify connects to 200+ apps.

## Supported action categories

| Category | Example actions |
| --- | --- |
| Billing and payments | Issue refunds, extend trials, re-trigger payouts |
| Ticketing and project management | Create tickets, create Jira issues |
| CRM | Update CRM fields and accounts |
| Orders | Make supported order changes |

<Info>
Billing integrations are separate from helpdesk integrations. Connecting your helpdesk doesn't connect your billing or payments app — each app an action depends on must be connected on its own. For helpdesks, see [Helpdesk connection guides](/helpdesk-connection-guides).
</Info>

## Operating modes

Operating modes control how much ify does without a human. Modes are configurable by ticket type.

| Mode | What ify does | Use for |
| --- | --- | --- |
| Autonomous | Resolves the ticket without human approval | Well-defined, low-risk ticket types |
| Human-in-the-loop | Proposes an action and waits for agent approval before executing it | Tickets that require approvals |
| AI Assist | Drafts a response or action suggestion for the agent to send | Tickets where agents stay fully in control |

## Guardrails and handoff rules

Guardrails and handoff rules are configurable instructions that define what ify will and will not do.

- **Guardrails** set the boundaries for ify's responses and actions.
- **Handoff rules** define when ify passes a ticket to a human agent.

When ify hands off a ticket, it preserves the conversation context and the approval trail, so the receiving agent can pick up where ify left off.

If an action you expect isn't available, see [Troubleshooting and handoff](/troubleshooting-and-handoff#unavailable-action).
